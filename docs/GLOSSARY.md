# Glossary

Contributor-facing definitions for terms with a precise project meaning.
User-facing vocabulary (entry vs entity, release) is governed by the
`writing-copy` skill and the guide-vocabulary rules; this file covers terms
as used in code, specs, and decision records. Each row names the module,
table or decision record that owns the term; where one word carries two
project meanings the row says so and names both.

## Library and data model

| Term | Meaning |
|---|---|
| **Artwork URL** | `/media-images/<content_url>`, built by `ImageFiles.web_path/1` and served by `Plugs.ImageServer` from the media directory's image cache; `?w=` selects a width derivative, `?v=` (the image's `updated_at`) makes the response immutable. A page emits one only when the entry's storage is available and the file is on disk — the projections withhold it otherwise (`Library.Views.ItemAvailability`, `Library.Images.with_presence/1`) — so the image server's uncached 404 is reached only by a file that vanished after it landed, which the server reports so the read models re-check. |
| **Capability** | A readiness predicate for one external integration (`MediaCentaur.Capabilities`; subjects `:tmdb`, `:prowlarr`, `:download_client`, `:usenet_download_client`). Ready means configured and the most recently persisted connection test succeeded. Gates user-visible features; flips broadcast `:capabilities_changed` on `capabilities:updates`. |
| **Container** | Two meanings. In `Library.Containers`, one of the four top-level addressable library entity types — `TVSeries`, `MovieSeries`, `Movie`, `VideoObject` — the thing a user browses to, carrying artwork, external ids and extras; `Movie` and `VideoObject` are also playable leaves. In `Library.PlayableItem`, the *owner* of a leaf, named by the `(container_type, container_id)` discriminator with `container_type` in `:movie | :episode | :video_object` — a set that includes `Episode` and excludes the two series types. |
| **Cut** | A version of a title whose *content* differs (theatrical vs director's cut, two-part edit): a second `PlayableItem` on the same container, labelled through its `name` field, with its own `WatchProgress` (ADR-059). Contrast rendition. |
| **Derived topic** | A `*:views` PubSub topic emitted by a `Cache.Worker`-driven projection after each ETS rebuild, payload `{:*_view_updated, view_id}` (`library:views`, `release_tracking:views`, `watch_history:views`, `status:views`, `shell:badges`). LiveViews subscribe here, never to source topics, for cache-driven data (`MediaCentaur.Topics` moduledoc, ADR-041). Derived events name the view; source events name the fact. |
| **Entity** | The code-facing word for a library record. An entity's `id` is a UUID v4 assigned once and never changed; it is the sole key for image directories, PubSub correlation (`{:entities_changed, ids}` on `library:updates`) and cross-references. User copy never says "entity" — see entry. |
| **Entity view** | The container-level read model of one entity, `MediaCentaur.Library.EntityView` (`:type`, `:name`, `:images`, `:seasons`, `:movies`, `:extras`, `:external_ids`, `:cast`, `:crew`, `:content_url`, …), consumed by the detail components as `attr :entity`, by the modal view models and by playback resolution. Produced by two adapters, one per source: `Library.Views.DetailItem.to_entity_view/1` from the detail projection and `Library.EntityShape.to_entity_view/2` from a preloaded container record. Formerly "the entity-map". |
| **Entry** | The user-copy word for a library record (movie, show, season, episode, extra) — the same thing code calls an entity; governed by the `writing-copy` skill and the guide-vocabulary rule. Not to be confused with the code structs `Console.Entry` (one captured log line), `Settings.Entry` (one settings row), `Person.Entry` (one title on a Friends-card shelf) and `Discovery.FeedEntry` — say *feed row* where the Feed's unit could be mistaken for a library entry. |
| **Extras name** | A directory name whose video contents are bonus features of the enclosing title rather than titles of their own (config `extras_dirs`, UI **Settings → Media Import → Extras folder names**). Read through `Settings.Config.extras_dirs/0` by every site that parses a path — discovery, import, review intake, the re-derive sweep. A *classification* rule: it decides what an admitted file is, where an ignore rule decides whether the file is admitted at all. `Parser`'s own literal list is the fallback for callers parsing a bare release name, and differs deliberately. |
| **File presence** | The durable record that a file was observed on disk and when: `Library.FilePresence`, table `library_file_presences`, one row per unique `file_path`, `last_seen_at` the only presence signal (ADR-045). Absence is derived, not stored — `Library.AbsenceSweeper` compares `last_seen_at` against a TTL, consulting `Watcher.MountStatus` first. `WatchedFile` and `ExtraFile` reference a presence row; the Watcher keeps no durable state. |
| **Hoist** | The movie-vs-collection presentation rule (ADR-050; `Library.Presentable`, `Library.PresentableQueries`): a `MovieSeries` with exactly one present child movie is hoisted away and that movie is presented as a `:movie` carrying a collection reference; with two or more present children the collection itself is presented. The rule reads present-on-disk counts, so the same id can resolve differently before and after a drive mounts. |
| **Settled** (a file, in Discovery) | A file whose identity is already decided, so `Pipeline.Discovery.process/1` skips it before parsing or searching: **linked** (`Library.Files.linked?/1` — owned by either presence table) or **dismissed** (`Review.dismissed?/1` — a person decided in review it is not library content). A `:pending` review row is *not* settled; it is an open question that `Watcher.Rescan.rescan_unlinked/0` exists to re-run. Distinct from an ignore rule, which keeps a path out of the library by *location* rather than by a decision about the file. |
| **Ignore rule** | A statement that some part of a media directory is not library content, in two matching modes compiled into one `Watcher.IgnoreRules` value: a **path rule** (config `exclude_dirs`) matching an absolute path and everything under it, and a **name rule** (config `skip_dirs`) matching a directory name case-insensitively wherever it appears — the distinction gitignore draws between patterns with and without a slash. `load/1` adds rules the user does not configure: `.staging` as a name rule, and the media directory's image-cache and image-staging roots as path rules. Invariant: no linked file's path may sit under one, enforced by `SettingsLive.IgnoreRulesLogic` where rules are created. Both kinds are one card, **Settings → Library → Ignore rules**. |
| **Media directory availability** | Whether a media directory's volume is reachable right now — live, per directory, `:available` or `:unavailable`; owner `Library.MediaFileAvailability` (`:persistent_term` reads, GenServer writes), fed by the watcher's `watcher:state` broadcasts and republished as `{:availability_changed, dir, state}` on `library:availability`. Per entity through its watched file's directory (`available_for_ids/1`). Consumed by the library projections, which set `available?` on every item and withhold the artwork of an unavailable one, and by the offline banner and Status tiles. Distinct from **file presence**, which is durable and per file; and from integration **Availability** below. |
| **Library content** | A path that is a recognised video file (`Watcher.VideoFile`) and that no ignore rule covers — `Watcher.IgnoreRules.library_content?/2`. The single admission predicate, asked at all three boundaries where a path enters the library: the inotify event filter, the directory scan (`Watcher.Walk`), and the recovery re-emit (`Watcher.Rescan.rescan_unlinked/0`). `ignored_dir?/2` prunes a subtree during traversal and cannot disagree with it. |
| **Retraction** | Removing recorded state for paths a newly-added ignore rule now covers — `Watcher.Rescan.retract_ignored/0`, run on an ignore-rule config change and as part of the boot `reconcile/0`. Travels as `{:files_removed, paths}` on `library:file_events`, the one representation of "the library no longer has these paths", consumed by `Library.FileEventHandler` (presence rows) and `Review.FileEventHandler` (review-queue rows). Files on disk are untouched; an imported file under a rule is reported, never retracted. |
| **Pillar** | One of the three state tiers every state-bearing module belongs to exactly once (ADR-041): Pillar 1, long-term storage (the database, sole source of truth); Pillar 2, in-memory state (ETS, `:persistent_term`, GenServer — unified under `MediaCentaur.Cache`); Pillar 3, real-time PubSub coordination. Schema moduledocs state their pillar placement (`Pursuits.Pursuit`, `Acquisition.Target`). |
| **Playable item** | The canonical playable leaf — the thing Play is pressed on: `Library.PlayableItem`, table `library_playable_items` (ADR-047). Identified by `(container_type, container_id)` plus `position`; carries `duration_seconds` and an optional `name` (version label). `WatchedFile`, `WatchProgress` and subtitle tracks hang off it, never off the container. |
| **Presentable** | The `{kind, id}` identity a user actually sees for any entity id — `kind` in `:movie | :movie_series | :tv_series | :video_object` — resolved by `Library.Presentable.resolve/1` (`Library.resolve_presentable/1`) by applying the hoist rule (ADR-050). **`presented_as`** is the same decision materialised onto each `Views.DetailItem` at projection build; `to_entity_map/1` dispatches on it instead of re-inferring from struct shape. The `CinematicShell` moduledoc reuses the adjective for any modal "grounded in a presentable subject". |
| **Projection** | An in-memory, pre-shaped read model (ADR-041): one named ETS table per view, owned by one `MediaCentaur.Cache.Worker` running a `MediaCentaur.Cache` implementation, rebuilt whole from the database on relevant source events, then broadcast on a derived topic. `Library.Views` is the public read API (`Browse`, `ContinueWatching`, `Detail`, `HeroCandidates`, `RecentlyAdded`, `Search`); reads fall back to the DB query when the worker is not running. |
| **Rendition** | A version of a title with the *same* content and a different encoding (HDR vs SDR, 2160p vs 1080p, remux vs web): a second `WatchedFile` on the same `PlayableItem` (ADR-059). Renditions share watch progress; the highest-quality one plays unless the user sets an active version. Rendition metadata is recomputable derived data (ADR-057). |
| **Source topic** | A PubSub topic carrying canonical events about the truth, broadcast only by its owning context (`library:updates`, `playback:events`, `watch_history:events`, `release_tracking:updates`, `acquisition:updates`, …); other contexts and `Cache.Worker`s subscribe (`MediaCentaur.Topics` moduledoc). Topics with a closed message set publish through a per-context `Events` chokepoint over the `Topics` transport (ADR-060). |
| **Watched file** | The join between a video file on disk and the one `PlayableItem` it plays back: `Library.WatchedFile`, table `library_watched_files`, fields `file_path`, `media_dir`, `playable_item_id`, `file_presence_id`. Created through `Library.Files.link/1`, which guarantees the presence row. Two watched files on one playable item are renditions. |

## Acquisition

| Term | Meaning |
|---|---|
| **Candidate** | A known release covering one or more units (ADR-055 vocabulary). Durable form: `Acquisition.Corpus.Candidate`, table `acquisition_corpus_candidates` — one release a search discovered, keyed by search key, carrying every `Search.SearchResult` field so it can be rehydrated for `Prowlarr.grab/1`. Solve-time form: `Acquisition.Planner.Option`, an identity-verified candidate with its classified coverage scope. |
| **Corpus** | The durable record of what acquisition searches found: `Acquisition.Corpus` — every search keyed by term plus result-affecting options (`Corpus.SearchRecord`) with its candidates. Consult-first: a key searched within the 30-minute freshness window is served with no indexer traffic, empty results included; rows older than 14 days are pruned. Not a wait-for-better mechanism. |
| **Search order** | The sequence of scopes a TV plan run searches — series term, season terms, episode terms — each against the residual, re-solving after each and halting when the residual is empty (`Acquisition.Jobs.RunPlan`, "residual-driven search"). Progress is broadcast per step as `PlanEvents.SearchProgress` (a step is one scope searched for one purpose, `:primary` or `:fallback`); `ViewModels.SearchProgressPanel` renders it, now inside the board's collapsed "How we searched" disclosure (UIDR-029). Formerly "the descent" down "the coverage ladder"; those words are retired. |
| **Scope** | How much of a series something covers: `:series`, `{:seasons, a, b}`, `{:season, n}`, `{:episodes, s, a, b}`, `{:episode, s, e}` (`Search.ReleaseCoverage`). A release has a scope, parsed from its name; a search term has a scope, the breadth it is shaped to find (series, season, episode — `Search.SearchTerms`); a plan run searches one scope per step. |
| **Gate** | Two usages. Per ADR-061, a gate expresses bounds and safety — quality floor/ceiling (`Search.Quality.acceptable?/1`), red flags (`Search.ReleaseRedFlags`) — and may exclude; ladders only order. In `Acquisition.Planner`, the *fit gate* (`pack_min_fit` against `wanted-in-span / span-total`) sets an over-broad pack aside as an offer rather than assigning it. |
| **Ladder** | Three meanings. (1) The *source ladder* (ADR-061; `Search.Quality` `@source_ladders`): a fixed ordering of source tokens within a resolution tier — `"fidelity"` remux > WEB-DL > BluRay encode > WEBRip/HDTV, or `"space"` BluRay encode > WEB-DL > WEBRip/HDTV > remux — selected by `auto_grab.size_preference`. (2) Retired: the *coverage ladder* was the scope axis complete series → season range → season pack → episode span → single episode (`Search.ReleaseCoverage` scopes; terms in `Search.SearchTerms`) — see **Scope** and **Search order**. (3) The *artwork promotion ladder* (UIDR-021): browsing, referenced, library tiers of TMDB imagery. |
| **Offer** | An over-broad pack the planner set aside instead of auto-assigning: an unfound unit whose only coverage is a pack that failed the fit gate (or a cour candidate, always offer-only) carries the pack the user can opt into, over-grab spelled out (`Acquisition.Planner` `offers`, `ViewModels.PlanBoard.Offer`, offer fields on `Plans.PlanUnit`). Never an auto-grab. |
| **Orphan** | A download-client queue item no in-flight pursuit row claimed — the second element of `Acquisition.QueueMatcher.match/2`'s `{paired, orphans}`. Rendered by `IncomingLive.OrphanQueue` as the "Other downloads" section (sideloaded torrents, title-match misses). The word also appears in its plain database sense (rows without a parent, ADR-045); the glossary sense is the queue one. |
| **Pack** | A release whose coverage scope spans more than one unit — `Search.ReleaseCoverage` scopes `{:season, n}`, `{:seasons, a, b}`, `:series`, and the episode span `{:episodes, s, a, b}`. One target for a pack covers many units through `Pursuits.TargetUnit` (ADR-055); packs are subject to fit gating and, in `auto` tracking mode, auto-commit (ADR-056). |
| **Plan** | The durable draft of one acquisition request from targeting through approval: `Acquisition.Plans.Plan`, table `acquisition_plans`, lifecycle `planning → ready → committed | discarded`, origin `manual` (media search) or `tracking` (release-tracking drop plan). One `Plans.PlanUnit` per wanted unit (`pending → found | unfound`, or `excluded`) carries its assignment and, per ADR-063, its per-unit outcome. Nothing grabs until `Plans.Commands.CommitPlan` turns the plan into a composite pursuit. |
| **Plan board** | The live display of a draft plan (`Acquisition.ViewModels.PlanBoard`, built by `Plans.Board.build/1`, rebuilt on `PlanEvents.Changed`; named the planning coverage board in UIDR-014). Per UIDR-029 it reads top to bottom: verdict sentence, episode grid of unit cells in season rows, outcome rows (below-preference, offers), kept releases, receipts footnote. An **empty board** (`PlanBoard.empty?/1`: ready, nothing found) carries the bookmark in its footer's primary slot — *Add to watchlist*, or the *On your watchlist* marker — in place of Approve (spec 2026-09-14). |
| **Gap verdict** | The board's one diagnosis sentence for a ready plan with unfound units (`Acquisition.ViewModels.GapVerdict`, UIDR-022): a closed set of *worlds* the counts prove — `:blind`, `:below_preference`, the calendar worlds `:unreleased` and `:in_theaters` (from the release window; movies only), `:no_evidence`, `:rejected`, `:nothing_live`, `:nothing_stale` — each a headline over an evidence line. `:searching` is the same slot while the plan is still planning. |
| **Release window** | Where a movie stands in its release sequence, read from TMDB's US release dates by type — theatrical, digital, physical — plus the primary `release_date`: `MediaCentaur.TMDB.ReleaseWindow`, built from a `get_movie` payload at a date. Its **stage** is `:unreleased` (every known date ahead), `:theatrical` (opened, no home release yet — within 180 days of opening, or with a home date known ahead), `:home` (a digital or disc release has passed), or `:unknown`. The **home release** is the earlier of the digital and physical dates: the first from which a release can exist on an indexer. Unrelated to the corpus *freshness window* and the history *window*, which are spans of time; this is a position in a sequence. Read live per board open, never stored on a plan. |
| **Profile** | ADR-061's word for the one semantic setting that selects the source ladder. In code and the Settings UI the same thing is `auto_grab.size_preference` (`Acquisition.AutoGrabSettings`), values `"fidelity"` (default) and `"space"`; the word "profile" does not appear in code. |
| **Pursuit** | One acquisition goal, durable across attempts: `Acquisition.Pursuits.Pursuit`, table `acquisition_pursuits` (ADR-039, ADR-055). Holds the recipe (`tmdb` or `prowlarr_query`), title, origin (`auto`/`manual`), criteria, and an outcome state folded from its units (`active | satisfied | partial | exhausted | cancelled`, `Pursuits.State`). Its history is the append-only `acquisition_pursuit_events` log written only through `Pursuits.Events.record/1`. |
| **Release** | Two meanings. In acquisition, a downloadable file an indexer offers for a title (`Search.SearchResult`, `Corpus.Candidate`, `Target.release_title`) — the only sense user copy may use, never a library entry. In release tracking, `ReleaseTracking.Release`, table `release_tracking_releases`: one calendar row per upcoming episode or movie date from TMDB, `released?/2` derived from `air_date`. |
| **Residual** | The wanted units the previous steps' solve left uncovered — the set the next step of the search order searches for (`Acquisition.Jobs.RunPlan` state `residual`, `PlanEvents.SearchProgress.residual_after`). A pack that fits removes its units from the residual; a sparse slice keeps them in it so the search continues to episode terms. `Pursuits.UnitOrder` orders units for the same walk. |
| **Target** | One grab attempt of one release for a pursuit: `Acquisition.Target`, table `acquisition_targets`, status `seeking → acquired → succeeded | failed | cancelled`. Per-release, not per-unit; carries only per-attempt facts (`attempt_count`, `next_attempt_at`, captured `quality`, `torrent_hash`, `content_path`). A unit's current attempt is `unit.current_target_id`. |
| **Target unit** | The join recording which units a target's release covers: `Acquisition.Pursuits.TargetUnit`, table `acquisition_target_units` (ADR-055). A single-episode target writes one row; a pack target writes one per covered unit. Deliberately a table rather than a `unit_id` column on targets. |
| **Unit** | One wanted thing — an episode, a movie, or one expanded query — inside a pursuit: `Acquisition.Pursuits.Unit`, table `acquisition_pursuit_units` (ADR-055). Carries the attempt thread (state `active → satisfied | exhausted | cancelled`, `current_target_id`, `tried_release_guids`, `attempt_count`, `awaiting_decision_at`, stall and seeder observations). `Plans.PlanUnit` is its plan-side sibling. Progress is always units satisfied over units wanted, never a target count. |
| **Want** | Durable per-unit acquisition intent owned by release tracking: `ReleaseTracking.Want`, table `release_tracking_wants` (ADR-056), maintained idempotently by `ReleaseTracking.Wants.sync_item/1`. Opens when a unit is released and not in the library; status `open | satisfied | dismissed`; `wanted_since` anchors patience and is never reset. Claim state is derived in Acquisition (`Plans.Claims`); `Acquisition.DropPlanner` batches open, unclaimed, search-due wants into a tracking plan. |
| **Title intent** | A person's whole standing intent about one title, and the only authored record in the tracking story: `Discovery.TitleIntent`, table `title_intents`, identity `(tmdb_id, media_type)`. Carries provenance (`:manual` / `:friend`, `note`, `activity_id`) and the **rung**; its render snapshot is the **TMDB store**'s, attached on read by `Discovery.Titles` (ADR-071) — a bare identity until the store first-contacts the title. Written only by a person, through `ReleaseTracking.set_rung/3`; library presence is derived at read time via `Library.ExternalIds` and is never a membership rule. Formerly `Discovery.WatchlistItem`, which held only List and below. |
| **Rung** | Where a title intent sits: `:ignored`, `:list`, `:follow`, `:grab` (UI: Ignore on a friend's feed row, the bookmark, Track release dates, Auto-grab — UIDR-042). **Off is the absence of a record**, never a stored value — which is what makes turning tracking off a deletion rather than a state to remember. There is no per-title grab policy: `TitleIntent.grabs?/1` says whether a title plans its drops, and `Settings.Preferences.PlanningMode` says whether the plan asks first. |
| **Ignored** (rung) | The lowest rung, below List: the person has decided the title is not for them. A record, unlike Off — an opinion, not the lack of one. Its one effect is keeping the title off the Feed (`FeedEntries`), every author's row for it; the activities, the Friends tab and the pennants are untouched. Not on the watchlist (`Discovery.list_watchlist/0` excludes it) and holds no artwork. Set by a friend's feed row's Ignore (`ignore_title`, with an undo toast) — the one way onto the rung; any rung at List or above replaces it — including Add to watchlist. |
| **Tracked title** | A title whose TMDB release calendar the app maintains: `ReleaseTracking.Item`, table `release_tracking_items`. Pure machinery, authored by nobody: it exists exactly while the title's rung is `:follow` or above **and** the title is not a film already in the library (which is complete). Derived in one place, `ReleaseTracking.set_rung/3`, and re-derived by `reconcile/2` when the library moves underneath an unchanged rung. |
| **Tracking controls** | The compact switches a listed title shows beside its release dates: Notify you via Coming up (Follow) and Auto-grab (Grab), `Components.Title.TrackingControls` (UIDR-042). Shown only for a title on the list (`TrackingControls.control_form/1`), with the rows `rows/1` decides: a movie the library owns has none, a movie that is out has Auto-grab only. The only thing that raises a title above List (UIDR-039). A download never moves a rung. |
| **Release dates** | What the app knows of a title's upcoming dates, as a plain readout beside the tracking switches on both title surfaces: `Components.ReleaseTracking.ReleaseDates` (spec 2026-09-14, iteration 2). A movie's theaters, digital and disc rows from the live `TMDB.ReleaseWindow` when the preview has landed, else from the tracked title's calendar; a series' next five dated episodes from the calendar. One word beside the row the app is acting on (Will download, Downloading, In your library). Replaced the release timeline. |
| **Tooltip** | The one glass label for any element carrying `data-tip`, positioned by the `Tooltip` hook (`hooks/tooltip.js`) on the single `#app-tooltip` element: to the right of the sidebar rail's links (only while collapsed), beneath every other anchor. Never a native `title` on a control. |
| **Bookmark** | The one-click beside a title's primary verb that lists it (`Components.Title.WatchlistToggle`; accessible name and tooltip *Toggle on watchlist*, the state in `aria-pressed`): outline off the list, solid on it. Sets List for a title with no record or an ignored one, Off for one on the list at any rung — removing from the watchlist is one act (UIDR-042). The only verb a title not on the list offers; once listed the tracking controls appear (UIDR-039). |
| **Following** | A rung of `:follow` or above — the one question that decides whether a tracked title exists (`TitleIntent.follows_releases?/1`). Grab, the one rung above it, plans a release when it drops; the calendar is kept either way. The UI word is "Tracking". Every rung move is one `Discovery.Events.RungChanged` carrying both ends; subscribers read their own threshold off it (the activities publisher reads List, not Follow). |
| **Download params** | The per-title acquisition settings — quality floor and ceiling, 4K patience — as `Acquisition.DownloadParams` embedded in `Acquisition.TitleDownloadParams`, table `title_download_params`, keyed by TMDB identity. Acquisition's, not release tracking's: they answer *how* to acquire, not *whether* to follow, and they outlive the title being tracked. Every field nil-means-inherit, so an absent row and an empty one mean the same thing. |
| **Approval policy** | Who commits a plan once it is `ready`: `automatic` (the approval gate, `Acquisition.Reactor.Handlers.plan_changed/1`, commits it when the result qualifies) or `review` (a person approves it on Downloads). A column on `acquisition_plans` (`Plans.Plan`), stamped at creation by whoever creates the plan (the drop planner and the Download button from the person's planning mode, `PlanningMode.approval_policy/1`; the picker from the planning mode the link carries, else the person's default) and never derived from `origin` at read time. |
| **Clean plan** | A solved plan in which every wanted unit (every unit not excluded) was found within its quality bounds — no gaps, no below-preference units, no pack offers (`Plans.clean?/1`). The qualifying test for an `automatic` manual plan; a tracking plan commits on any found unit because its want ledger retries the remainder. |
| **Download scope** | What the Download button's plan for a series covers (`Plans.DownloadScope`): `:first_season` — the lowest season numbered 1 or higher with a pickable episode, exactly those episodes; `:everything` — the picker's default, every pickable episode. Neither follows the series (ADR-066). Movies have one scope. Chosen by the scope select beside a series' Download button (`GlassMenu.menu_select`): Season 1, All seasons, or *Choose episodes* — a third select value (`Title.ModalState.scope_choice/0`), not a scope, under which Download opens the picker on Incoming with the click's planning mode instead of planning. |
| **Planning mode** | What the Download button on a title the library does not own does when pressed: *auto-select best release* (`:auto_select_best_release`, approval policy `automatic`: a clean plan commits with nobody looking, anything else parks on Incoming) or *manually select release* (`:manually_select_release`, approval policy `review`: the plan is created and its board opens on Incoming). The person's default is `Settings.Preferences.PlanningMode` (key `default_planning_mode`, default manual); the button's menu offers the other. The picker on Incoming carries the same split: its main segment performs the mode its link carries (`IncomingLive.PlanQuery`), else the person's default, and its menu names the other. The mapping to a policy is `PlanningMode.approval_policy/1`, which also stamps every tracking plan (UIDR-042). |
| **Acquisition state** | The per-title fact a surface listing unowned titles shows (`Acquisition.TitleStates.for_refs/1`): `:downloading` (a pursuit in flight), `:needs_review` (a draft plan `ready`), `:planning` (a draft solving); absent when nothing is in flight. A pursuit outranks a draft. |

## Outbound integrations

The vocabulary of the recurring-traffic audit (closed 2026-09-18; the
campaign file was removed at completion — see git history), which gave
every recurring outbound request a rule about what it does while the
server it talks to cannot answer.

| Term | Meaning |
|---|---|
| **Integration** | A server the app talks to on its own: Prowlarr (and the indexers behind it), a download client, TMDB and its image CDN, GitHub, a Nostr relay. The codebase's existing word — `Capabilities.save_integration/2`, `IntegrationHealth`. |
| **Availability** | The published runtime answer per integration: `:up`, or `{:down, since, reason}` — `MediaCentaur.IntegrationAvailability`, one `Status` per integration in `:persistent_term`, written by exactly one module each (`Search.ProwlarrAvailability` for `:prowlarr` and both hand-offs, `TMDB.Availability` for `:tmdb`). `available?/1` is the gate callers use: configured (`Capabilities`, the durable half) **and** up (the runtime half). Reasons: `:unreachable`, `:rejected` (401/403), `:rate_limited` (429), `:blind` (Prowlarr answers, every enabled indexer backed off), `:client_unavailable` (the hand-off). Not `Library.MediaFileAvailability`, which is whether one entity's file is reachable on disk. |
| **Hand-off** | Prowlarr's own link to a download client, which the app cannot see directly; it fails as HTTP 500 `DownloadClientUnavailableException` on a grab. One availability value per protocol slot: `{:handoff, :usenet}`, `{:handoff, :torrent}`. Distinct from `Downloads.Connectivity`, which grades the app's *own* link to a client. |
| **Probe** | A free request whose only purpose is to learn whether a down integration can do the job again, so no metered request is spent finding out: the indexer roster read for `:prowlarr`, `downloadclient/testall` for a hand-off, `GET /configuration` for `:tmdb`. Runs on a schedule (`Search.ProbeJob` 60 s, `TMDB.ProbeJob` 5 min) **only while that integration is down**; while up, real requests are the evidence. |
| **Held work** | A job or tick that consulted availability, found its integration down, and waits without spending a request — `Jobs.PursueTarget`, `Jobs.RunPlan`, `DropPlanner`, `TMDB.CheckJob`, `TmdbArtwork.ensure/2`. An Oban job holds by snoozing at the probe cadence, which bounds recovery to one cadence; a GenServer tick re-arms at it. Recovery is also pushed: `{:integration_availability_changed, integration, :up}` on `Topics.integration_availability_updates/0`. |
| **Metered integration** | One that counts requests against a limit or escalates a back-off when hit repeatedly — TMDB and its CDN, Prowlarr's live searches and grabs, GitHub, Nostr relays. A **free integration** does neither (the download clients on the LAN) and keeps polling at its normal cadence during an outage; only its log noise is capped, to one line per grade transition. Cost, not cadence, decides which sources get a gate. |

## TMDB store

The vocabulary of `tmdb-fetch-policy` (ADR-071): the app asks TMDB only
when it is seeking new information, and holds one record per title.

| Term | Meaning |
|---|---|
| **TMDB store** | `MediaCentaur.TMDB.Store`: one `TitleRecord` per `(media_type, tmdb_id)` — TMDB's last detail answer, its ETag, when it was fetched and last changed, and the derived schedule — with one `SeasonRecord` per stored season. The only module that calls a `TMDB.Client` detail endpoint. Not the **response cache** (`HttpClient.Cache`, ADR-064), which is per URL, in memory and policy-free. |
| **Fetch / request** | A fetch is a call into `TMDB.Client`; a request is a fetch that reached TMDB. A response-cache hit is not a request. |
| **First contact** | The fetch that creates a stored title the app has never held — `Store.ensure/2`. The only fetch that is not a check. |
| **Check** | A conditional revalidation of a stored title with its own ETag — `Store.check/2`; a 304 means unchanged. Open seasons are checked with their series. Made by `TMDB.CheckJob` when due, or by *Refresh from TMDB* (UIDR-044). |
| **Reference** | A context's hold on a title — a tracked item, a title intent, an open pursuit, a friend's activity — collected by `TMDB.References` from `TMDB.References.Provider`s. Every reference keeps the record and its artwork alive; only the providers that answer `schedules_checks?/0` schedule checks — tracked, listed, planned and owned titles; a friend's activity never does. Scheduled-ness is this query at check time, never a stored flag. |
| **Full fetch** | TMDB's whole answer for a title or season, credits included — `Store.fetch_full/2`, `fetch_full_season/3`. The import's one fetch per library entity it creates (the credits are the library's, not the store's); the answer replaces the stored record as a changed check would. Not a check: nothing asks whether the title is due. |
| **TMDB projection** | A fact rebuilt from a stored title's payload, never fetched on its own: calendar rows, render snapshots, release windows, the targeting universe, artwork paths — and the library's own TMDB fields, season episode lists and episode details, re-applied by `Pipeline.TmdbProjection` on `{:tmdb_title_changed, ref}` (ADR-071 §2.6). Not the ETS read-model **Projection** of ADR-041 above. |
| **Release facts** | The fields that change over a title's life: typed release dates, air dates, episode lists, season count, status, next episode to air. Everything else is fixed once known. |
| **Settled title** | One whose release facts cannot change again: a movie at release stage `:home`, or 180 days past its primary date with no typed home date, or canceled; a series ended or canceled with no air date ahead. Never due. |
| **Next known event / due** | The earliest release fact ahead of today. A check is due the day after it (noon UTC) or seven days after the last fetch, whichever is first — `TMDB.Schedule.plan/5`. |
| **Open season** | A stored season still checked with its series: the latest numbered season, or one holding an episode with no air date or one ahead of today — `TMDB.Schedule.open_season?/3`. |

## Time series

The vocabulary of the strip charts (design
`docs/superpowers/specs/2026-09-19-strip-chart-design.md`, ADR-070).

| Term | Meaning |
|---|---|
| **Time series** | Counts of an event along time, per key — requests per upstream. `MediaCentaur.TimeSeries` is the mechanism (store, fold, snapshot); a **tenant** (`HttpClient.Traffic`) owns one series family. |
| **Time bucket** | The span one bar covers, and the span the store counts into. Qualified because *bucket* alone is an incident group (below). In `TimeSeries` code, `bucket` means the time bucket. |
| **Resolution** | One of the four stored bucket widths — 10 s kept 1 h, 1 min kept 6 h, 10 min kept 2 d, 1 h kept 31 d (`TimeSeries.Resolution`). Every event is counted into all four. Not "tier", which already has two meanings here. |
| **Window** | The span a viewer selects — 5m, 1h, 5h, 1d, 1w, 1mo (`TimeSeries.Window`) — and the bar width and count it implies. One window drives every strip on a surface. Bars of 20 minutes and wider align to the machine's local midnight (`TimeSeries.LocalDay`, from the OS offset; the app has no time-zone database). |
| **Round-robin store** | `TimeSeries.Store`: the ETS table whose rows past their resolution's retention are swept once a minute, so the row count is bounded by construction. Counting happens in the caller with atomic ETS operations; the process only sweeps and snapshots. |
| **Snapshot** (time series) | The store's on-disk copy, `<database dir>/<tenant>.snapshot`, written whole and atomically once a minute when anything changed and on clean shutdown; loaded on boot; ignored on version mismatch (ADR-070). Unrelated to a `Cache.Worker` projection snapshot. |
| **Strip chart** | `MediaCentaurWeb.Components.StripChart`: N **strips** (a name column with figures beside a short wide chart) sharing one window, one time axis and one synced cursor. The `StripChart` hook owns the strips; the server sends **frames**. |
| **Frame** | One push of data from the LiveView to the `StripChart` hook — window, schema, and per strip its figures and columns (`StripChart.Feed` moduledoc). |
| **Feed** | `StripChart.Feed`: the LiveView-side lifecycle — window from the URL, one frame on becoming active, one every ten seconds while active and the tab is visible. |
| **Traffic** | `MediaCentaur.HttpClient.Traffic`: the HTTP layer's time series of requests per upstream (requests, failed, cached, latency sum and max), plus the twenty most recent requests and each upstream's last outcome. Replaced `HttpClient.Stats`. |

## Observability

| Term | Meaning |
|---|---|
| **Bucket** | An incident group (this row); a *time bucket* is the span of one bar, see § Time series. The in-memory cache projection of an incident that `ErrorReports.Buckets` (GenServer) serves to the Status page: `ErrorReports.Bucket`, keyed by fingerprint — 16 hex chars of `sha256(component || normalized_message)` (`ErrorReports.Fingerprint`) — with count, first/last seen, severity and up to five redacted sample lines. `:subsystem` faults appear under synthetic fingerprints. Unrelated: `UpcomingFeed.bucket_order/0` names the Coming up shelf's relative-time groups. |
| **Component** | The atom every `MediaCentaur.Log` macro call is tagged with (`Log.info(:pipeline, …)`), carried as `:component` logger metadata into `Console.Entry` (never nil) and used by the Console chip filter — app: `:watcher`, `:pipeline`, `:tmdb`, `:playback`, `:library`, `:acquisition`, `:nostr`, `:social`, `:system`; framework: `:phoenix`, `:ecto`, `:live_view` (`Console.View.known_components/0`). The same atom is half of an incident's grouping key and the registry key for a subsystem's `IncidentContext` (`:diagnostics_contributors`). Distinct from a Phoenix function component. |

Origin `:log` (minted by `ErrorReports.LogHandler` from warning/error log lines, grouped by fingerprint), `:subsystem` (raised and auto-resolved by `ErrorReports.Evaluator` from an assessor's `assess/0`, grouped by `{component, kind}`), or `:user` (never grouped). ADR-054: a fault in a polled external dependency is subsystem health, not a log incident; `mc_incident: :skip` keeps such a log out of the `:log` track. |
| **Incident context** | The behaviour a subsystem implements to take part in diagnostics: `ErrorReports.IncidentContext` — `assess/0` (cheap health probe returning `:ok` or `{:fault, kind, severity, ids}`), `gather/1` (structured context for an incident), `vitals/0`; all optional. Discovered through the config-driven registry `ErrorReports.Contributors`, so `ErrorReports` has no compile-time dependency on any subsystem. Implementations: `Downloads.IncidentContext`, `Search.IncidentContext`, composed into one condition by `Acquisition.IncidentContext`. |

Wire field `sentiment`, absent meaning none; nullable column, nil on every other kind's row. Not the watchlist note — a title intent's `note` is the person's own, or the review text copied in as provenance when the title was listed from a friend's review. |
